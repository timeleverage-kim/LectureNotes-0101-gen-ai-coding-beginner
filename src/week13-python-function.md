## 2. 🧠 개념 파트 · 함수란? (45분)

### 2-1. 함수 = 이름 붙은 레시피

> 🧠 **비유: 자판기**
> 자판기에 **동전을 넣으면(입력)** → 안에서 알아서 **처리**하고 → **음료가 나와요(출력)**. 안이 어떻게 돌아가는지 몰라도 **버튼(이름)만 누르면** 돼요. **함수**도 *"재료(인자)를 넣으면 → 결과(`return`)를 돌려주는"* 자판기예요.

```text
              ┌────────────────────┐
   재료  ───▶ │  함수 get_grade()    │ ───▶  결과
 (4점, 4문제) │ (등급을 정하는 레시피) │      "🏆 퀴즈 박사"
              └────────────────────┘
```

> 📖 **새 용어 풀이**
> | 용어 | 쉬운 뜻 |
> |:--|:--|
> | **함수(function)** | 이름을 붙인 **할 일 묶음** (레시피) |
> | **정의(def)** | 함수를 **만드는** 것 (레시피를 적어 두기) |
> | **호출(call)** | 함수를 **실행하는** 것 (이름 + `( )`) |
> | **매개변수(인자)** | 함수에 **넣어 주는 재료** |
> | **`return`** | 함수가 계산한 **결과를 돌려주는** 것 |
> | **독스트링 `"""…"""`** | 함수 맨 위에 쓰는 **한 줄 설명** |

### 2-2. 함수의 모양

```python
def add(a, b):          # def = 정의. add 라는 이름, 재료는 a, b
    return a + b        # 결과를 돌려준다 (들여쓰기!)

result = add(3, 4)      # 호출! 3과 4를 넣으면 7을 돌려받아요
print(result)           # 7
```

```text
  def  이름 (재료들) :
       할 일 …
       return 결과
```

> 📖 **JS와 비교** `function add(a, b) { return a + b; }` → 파이썬은 `def add(a, b):` + 들여쓰기!

### 2-3. `print` 와 `return` 의 차이 🧪

```python
>>> def add_print(a, b):
...     print(a + b)
...
>>> def add_return(a, b):
...     return a + b
...
>>> x = add_print(3, 4)
7
>>> x
>>> y = add_return(3, 4)
>>> y
7
```
| | `print` | `return` |
|:--|:--|:--|
| 하는 일 | 화면에 **보여 줄** 뿐 | 값을 **돌려줘서** 다른 곳에서 **쓸 수 있게** 해요 |
| 비유 | 요리를 **손님 앞에서 보여 주기만** | 요리를 **접시에 담아 건네주기** |

> 💡 *"결과를 다른 계산에 쓰고 싶으면 `return`!"* 이 기본 규칙이에요.

### 라운드 1 🅿️ — 함수로 정리하고 등급 더하기 (리팩터링)

> 📖 **새 용어 풀이 (프롬프트에 쓸 말!)**
> | 용어 | 쉬운 뜻 |
> |:--|:--|
> | **함수(function)** | 이름을 붙인 **할 일 묶음** (레시피) |
> | **정의(`def`) / 호출** | 만들기(레시피를 적어 두기) / 실행하기(이름 + `( )`) |

> | **리팩터링** | **동작은 그대로** 두고 코드의 **모양만 정리**하는 것 |

**Step 1. 요구 정리표 — 어떤 함수들로 나눌까?**

| 일 | 만들 함수 | 받는 재료 → 돌려주는 값 |
|:--|:--|:--|
| 내 답이 맞는지 판단 | **정답 확인 기능** | 내 답, 정답 → 맞음 / 틀림 (앞뒤 빈칸 무시) |
| 점수에 따라 등급 정하기 | **등급 기능** | 맞힌 개수, 전체 → 등급 글자 |
| 퀴즈 전체 진행 | **퀴즈 진행 기능** | 문제 묶음 → **맞힌 개수** |
| 시작 | **"직접 실행했을 때만"** 시작되는 부분 | 게임 시작 → 점수·등급 출력 |

| 등급 규칙 | 값 |
|:--|:--|
| 전부 맞힘 | `🏆 퀴즈 박사` |
| **절반 이상** (딱 절반 포함) | `👍 퀴즈 도전자` |
| 그 외 | `🌱 퀴즈 새싹` |

### 라운드 2 🅿️ — "예상 결과"를 먼저 적는 자동 확인 파일

> 🧠 **비유: 정답지를 먼저 만들어 두고 채점하기** 선생님은 시험을 내기 전에 **정답지를 먼저** 만들어 두죠? 함수가 낸 답을 **정답지와 비교**해서 맞는지 컴퓨터가 **대신 채점**하는 거예요.

> 📖 **새 용어 풀이**
> | 용어 | 쉬운 뜻 |
> |:--|:--|
> | **`assert`** | *"이 문장은 참이어야 한다!"* 고 선언. **거짓이면 에러** |
> | **자동 확인(테스트)** | 예상 결과와 실제 결과를 컴퓨터가 **대신 비교**하는 것 |
> | **`from 파일 import 함수`** | 다른 파일에서 **함수만 빌려 오기** |

```python
assert get_grade(4, 4) == "🏆 퀴즈 박사"
#      ↑ 이 호출의 결과가     ↑ 이것과 같아야 한다!
```
- 같으면 → **조용히 통과** / 다르면 → **`AssertionError`** 🚨

**요구 정리표 — 예상 결과표 (내가 먼저 적는 정답지!)**

| 상황 | 예상 결과 |

| 내 답 "부산", 정답 "서울" | 틀림 |
| 4문제 중 4개 맞힘 | `🏆 퀴즈 박사` |
| 4문제 중 2개 맞힘 | `👍 퀴즈 도전자` (딱 절반도 도전자!) |
| 4문제 중 1개 맞힘 | `🌱 퀴즈 새싹` |

### 4-3. 🧪 자동 확인이 "잡아내는" 모습 보기 ⭐

`quiz_game.py` 의 `get_grade` 에서 `score >= total / 2` 를 **`score > total / 2`** 로 살짝 바꾸고 `check_quiz.py` 를 실행해 보세요.

```text
Traceback (most recent call last):
  File "check_quiz.py", line 8, in <module>
    assert get_grade(2, 4) == "👍 퀴즈 도전자"
AssertionError
```
→ **8번째 줄의 확인이 실패!** *"딱 절반(2/4)일 때 도전자가 나와야 하는데 아니야!"* 라고 **컴퓨터가 알려 줘요.** (확인했으면 **되돌리세요.**)

```text

```

> 🤖 **AI와 함께 쓸 때 특히 좋아요.** AI가 코드를 고쳐 줬을 때 **`python check_quiz.py` 한 번**으로 *"멀쩡한 부분을 망가뜨리지 않았나?"* 를 확인할 수 있어요.

> 📖 **`if __name__ == "__main__":`** 는 *"안전 스위치"* 예요. 직접 실행하면 게임이 시작되고, 다른 파일에서 `import` 해서 함수만 빌릴 땐 게임이 **저절로 시작되지 않아요.** 지금은 *"주문 같은 문장"* 으로 기억해도 충분해요!

```text
  메인(맨 아래)
   ├─ play(quiz_list)  ─────▶ my_score 를 돌려받음
   │    └─ 각 문제마다 is_correct() 호출
   └─ get_grade(my_score, 전체) ─▶ 등급 글자를 돌려받아 출력
```

> 💡 **`print` 와 `return` 의 차이**는 2-3 놀이터 체험을 다시 떠올려 보세요. *"결과를 다른 곳에서 쓰고 싶으면 `return`!"*

## 💪 도전 A · B (우수 학생용 중급 확장)

> 🧭 **도전도 두 레인으로!** ① 🅿️ **프롬프트 점검표**를 지켜 Antigravity에게 시키고 → ② 🅲 **코드 점검표**로 결과를 확인하세요. *(AI가 준 코드가 안 돌아가면 에러 메시지를 붙여 넣어 고치고, 마지막에 **내 말로 코드를 설명**해 보세요.)*
> ✍️ **프롬프트는 코드가 아니라 일상어로!** 아래 코드 조각은 *읽고 이해하기 위한 예시*예요. AI에게는 코드를 붙여 넣지 말고 **"무엇을 어떻게 되게 하고 싶은지"** 를 말로 설명해서 시켜 보세요.

### 💪 도전 A · "오답 노트"
게임이 끝난 뒤 **틀린 문제만 다시 보여 주는** 오답 노트 기능을 만들어 보세요.

```python
wrong = []                              # 틀린 문제를 모아 둘 빈 리스트

# play() 안, 오답일 때
wrong.append(quiz)

# 게임이 끝난 뒤
if len(wrong) > 0:
    print("📒 오답 노트")
    for quiz in wrong:
        print("-", quiz["question"], "→ 정답:", quiz["answer"])
```
**목표**: ① `play()` 가 **맞힌 개수와 틀린 문제 리스트 두 가지**를 돌려주게 하기 (힌트: `return score, wrong` → 받을 땐 `my_score, wrong = play(quiz_list)`) ② 틀린 문제가 **없으면** *"완벽해요! 오답이 없어요 👏"* 출력 ③ 오답 노트를 **다시 풀어 보는** 복습 모드 만들기

### 💪 도전 B · "내 힘으로 자동 확인 늘리기"
`is_correct` 의 경계 상황을 **스스로 떠올려서** `assert` 로 확인해 보세요.

| 상황 | 예상 결과 | `assert` 로 써 보기 |
|:--|:--|:--|
| 앞뒤 공백이 있는 정답 `" 서울 "` | `True` | `assert is_correct(" 서울 ", "서울") == True` |
| 빈 입력 `""` | `False` | ? |
| 대소문자 `"Seoul"` vs `"seoul"` | 지금은 `False` | ? |

**목표**: ① 위 표를 `assert` 로 **모두 작성**하고 실행 ② 대소문자를 **무시하도록** `is_correct` 를 고치기 (힌트: `.lower()` — 9주차 이름 마법사에서 배웠어요!) ③ 고친 뒤 **기존 assert가 여전히 통과하는지** 확인 → *"자동 확인 덕분에 안심하고 고칠 수 있다"* 를 체감하고 한 줄 소감 적기

> 💭 **먼저 `assert`(정답지)를 쓰고, 그다음에 코드를 고치면** 더 믿을 수 있어요. 이 순서로 해 보고 순서의 차이를 느껴 보세요!
