## 2. 파트 1 · 폴더·파일·확장자 마스터

### 2-1. 컴퓨터 안은 "서랍장"

> 🧠 **비유: 서랍장과 서류**
> 컴퓨터 저장 공간은 **서랍장**이에요. **폴더 = 서랍**, **파일 = 서랍 속 서류**. 서랍 안에 작은 서랍(폴더)이 또 있을 수 있죠.

```text
📁 코딩수업                  ← 폴더 (서랍)
 ├─ 📁 week01                ← 폴더 안의 폴더
 │   └─ 📄 index.html        ← 파일 (서류)
 └─ 📁 week02
     ├─ 📄 index.html
     └─ 🖼️ me.svg
```

| 용어 | 쉬운 뜻 | 예 |
|:--|:--|:--|
| **폴더(디렉터리)** | 파일을 담는 서랍 | `코딩수업` |
| **파일** | 내용이 담긴 서류 한 장 | `index.html` |
| **경로(Path)** | 파일이 있는 **주소** (어느 서랍의 어느 서랍) | `C:\dev\week02\index.html` |
| **확장자** | 파일 이름 끝의 **종류 꼬리표** | `.html` `.css` `.js` `.py` `.txt` |

### 2-2. 확장자 보이게 하기 (꼭!)

확장자는 **파일의 종류**를 알려 줍니다. 그런데 컴퓨터가 처음에는 **숨겨 놓는** 경우가 많아 실수가 잦아요.

| 운영체제 | 켜는 방법 |
|:--|:--|
| **Windows** | 파일 탐색기 → **보기** → **표시** → **파일 확장명** 체크 |
| **Mac** | Finder → 메뉴 **Finder → 설정 → 고급** → **모든 파일 확장자 보기** 체크 |

## 3. 파트 2 · 🧭 Antigravity 사용법과 터미널

### 3-1. Antigravity란? — "AI 조수가 들어 있는 코드 편집기"

> 🧠 **비유: 글쓰기 앱 + 똑똑한 비서**
> 메모장도 글을 쓸 수 있지만, **코드 편집기**는 코드를 색깔로 구분해 주고 오타를 알려 주는 *코딩 전용 글쓰기 앱*이에요. **Antigravity**는 거기에 **AI 비서(에이전트)** 가 붙어 있어서, *"이런 걸 만들어 줘"* 라고 하면 **파일을 직접 만들고 고치고 실행**해 줘요.

```text
┌──────────────────────── Antigravity ────────────────────────┐
│ 📁 파일 탐색기 │ 📝 에디터 (코드를 읽고 고치는 곳)  │ 🤖 에이전트 패널   │
│  my-portfolio │  <h1>안녕하세요!</h1>             │  (AI와 대화하는 곳) │
│   └ index.html│                                 │  프롬프트 입력      │
│               ├──────────────────────────────────│  계획서(아티팩트)   │
│               │ ⌨️ 터미널 (글자로 명령하는 곳)       │  결과 요약          │
└───────────────┴──────────────────────────────────┴───────────────────┘
```

| 화면 부분 | 하는 일 | 이 수업에서 하는 행동 |
|:--|:--|:--|
| 📁 파일 탐색기 | 폴더·파일 목록 | 어떤 파일이 **생겼는지** 확인 🅲 |
| 📝 에디터 | 코드를 읽고 고치는 곳 | AI가 쓴 코드를 **눈으로 읽기** 🅲 |
| 🤖 에이전트 패널 | AI와 대화하는 곳 | **프롬프트 입력**, 계획서 읽기 🅿️ |
| ⌨️ 터미널 | 명령을 실행하는 곳 | 프로그램 실행, Git 명령 🅲 |
| 📋 아티팩트 | AI가 남기는 **계획서·할 일 목록·결과 요약** | 계획을 읽고 **승인/수정 요청** 🅿️ |

> 📝 **Antigravity는 빠르게 발전하는 도구라서** 화면 이름·배치·메뉴가 수업 시점에 조금 다를 수 있어요. 화면이 교안과 다르면 **"역할"** 로 찾으세요. 에디터·에이전트 패널·터미널은 그대로입니다. (구성: *에디터 화면*과 여러 에이전트를 관리하는 *에이전트 매니저* 두 가지 창이 있어요. 우리는 **에디터 화면**을 주로 써요.)

### 3-3. 표준 작업 루프 — 앞으로 14주 동안 계속 써요 ⭐

```text
 🅿️ 프롬프트 파트                                    🅲 코드 파트
 ① 요구 정리 (표) ─▶ ② 프롬프트 작성 ─▶ ③ 점검표 ✅ ─▶ ④ 에이전트에 보내기
        ─▶ ⑤ 계획서(아티팩트) 읽고 승인/수정

                                    ─▶ ⑧ 코드 읽기 ─▶ ⑨ 틀린 곳 고쳐 달라기 / 되돌리기
                                    ─▶ ⑩ 저장(커밋)
```

**🅿️ 프롬프트 점검표 (보내기 전)**

| # | 점검 | ✔ |
|:--:|:--|:--:|
| 1 | **역할**이 있나요? | ☐ |
| 2 | **목표**가 한 문장으로 분명한가요? | ☐ |
| 3 | **파일 이름·버튼 이름표·색 코드**처럼 **정확히 맞아야 하는 약속만** 적었나요? (나머지는 코드 없이 **일상어**로!) | ☐ |
| 4 | **건드리지 말아야 할 것**(예: *"HTML은 바꾸지 마"*)을 적었나요? | ☐ |
| 5 | **"먼저 계획을 보여 줘"** 를 넣었나요? | ☐ |
| 6 | 개인정보·비밀번호가 **없나요?** | ☐ |

**🅲 코드 점검표 (받은 뒤)**

| # | 점검 | ✔ |
|:--:|:--|:--|
| 1 | **계획서(아티팩트)** 와 실제 만들어진 파일이 같은가? | ☐ |
| 2 | **실행해 봤나요?** (브라우저 / 터미널) | ☐ |
| 3 | **동작 점검표**의 항목이 모두 통과했나요? | ☐ |
| 4 | 코드를 **한 번은 읽어 봤나요?** (모르는 줄은 AI에게 물어보기) | ☐ |
| 5 | `git diff` 로 **바뀐 곳만** 확인했나요? (엉뚱한 곳 수정 여부) | ☐ |
| 6 | 마음에 들면 **저장(커밋)**, 아니면 **되돌리기** | ☐ |

> 💡 **AI가 만든 코드가 교안의 "기준 코드"와 달라도 괜찮아요!** 같은 일을 하는 코드는 여러 가지예요. 중요한 것은 **① 내 요구가 다 들어갔는지 ② 동작 점검표가 통과하는지**예요. 도저히 안 풀리면 기준 코드를 복사해서 다음 단계로 가도 좋아요. (단, **읽는 것은 꼭!**)

### 3-4. 터미널: 글자로 컴퓨터에게 말하기

> 🧠 **비유: 문자 메시지로 하는 심부름** 마우스는 *"저거!"* 하고 가리키는 것이고, 터미널은 **말로 정확히 시키는 것**이에요.

**터미널 여는 방법**: 편집기 메뉴 **Terminal → New Terminal**.

| 하는 일 | 명령 | 뜻 |
|:--|:--|:--|
| 지금 어디? | `pwd` | 현재 폴더 위치 보기 |
| 목록 보기 | `ls` | 폴더 안 파일 보기 |
| 폴더 만들기 | `mkdir 이름` | 새 서랍 만들기 |
| 폴더 들어가기 | `cd 이름` | 그 서랍으로 이동 |
| 한 칸 위로 | `cd ..` | 바깥 서랍으로 나오기 |
| 화면 지우기 | `cls` (Windows) / `clear` (Mac) | 깔끔하게 |

> 💡 `Tab` 키는 **이름 자동완성**, 위쪽 방향키(↑)는 **이전에 친 명령** 불러오기!

### 3-5. 🧪 실습 3 · 설치 점검 + 🅿️ AI에게 "명령어 해설" 시키기

터미널에 하나씩 입력해서 **버전 숫자**가 나오는지 확인하세요.

```bash
git --version
python --version      # Mac이면 python3 --version
```

| 명령 | 정상 출력 예 | 안 나오면 |
|:--|:--|:--|
| `git --version` | `git version 2.43.0` | Git 설치 후 **터미널을 껐다 켜기** |
| `python --version` | `Python 3.13.1` | Python 설치 후 터미널 재시작 |

> 📥 **설치**: **Git** — `git-scm.com` (옵션은 모두 기본값). **Python** — `python.org` 에서 **3.10 이상**, ⚠️ Windows는 **`Add python.exe to PATH` 반드시 체크!** (9주차부터 써요.)

🅿️ **에이전트에게 모르는 명령 물어보기 (읽기 전용 프롬프트)**

> 🤖 **프롬프트 (질문만, 파일은 건드리지 마)**
> ```text
> 터미널에서 쓰는 pwd, ls, cd, mkdir 명령이 각각 뭘 하는지 초등학생도 알 수 있게 비유로 설명해 줘.
> 파일은 만들거나 수정하지 말고, 설명만 해 줘.
> ```

🅲 **확인**: AI의 설명을 읽고, **실제로 터미널에서 `pwd`, `ls` 를 쳐서** 설명과 같은지 확인하세요. 다르면 AI가 틀린 거예요!

> 🔧 **문제 해결**
> | 증상 | 원인 | 해결 |
> |:--|:--|:--|
> | `'git'은(는) 인식되지 않습니다` | 설치 직후 터미널이 모름 | **편집기를 완전히 종료 후 다시 열기** |

## 4. 파트 3 · Git: 코드의 "게임 세이브"

### 4-1. Git이란?

> 🧠 **비유: 게임의 세이브 포인트**
> 어려운 보스를 만나기 전에 **저장**해 두면, 져도 그 지점부터 다시 할 수 있죠? **Git**은 **코드의 세이브 기능**이에요. 코딩하다 망가져도 **"어제 상태로 돌아가기"** 가 되고, **"언제 무엇을 왜 바꿨는지"** 일기처럼 남아요. AI가 코드를 마구 바꿔 놓았을 때 **되돌리는 안전장치**이기도 합니다.

> 📖 **새 용어 풀이**
> | 용어 | 쉬운 뜻 |
> |:--|:--|
> | **Git** | 변경 기록을 저장하는 프로그램 (세이브 기능) |
> | **저장소(repository, repo)** | Git이 관리하는 **프로젝트 폴더** |
> | **커밋(commit)** | 지금 상태를 **세이브**하는 것 (사진 한 장 찍기) |
> | **GitHub** | Git 저장소를 인터넷에 **백업·공유**하는 웹사이트 (클라우드 앨범) |
> | **push** | 내 컴퓨터의 저장 기록을 GitHub로 **올리기** |

### 4-2. Git의 흐름 그림

```text
  ✏️ 작업 폴더        🛒 장바구니           📸 앨범(내 컴퓨터)        ☁️ GitHub
 (파일을 고침)  ──▶  (이번 저장에 넣을 것)  ──▶  (커밋으로 저장)   ──▶  (인터넷 백업)
                     git add                git commit              git push
```

### 4-3. 처음 한 번만: 이름과 이메일 등록

```bash
git config --global user.name "내이름"
git config --global user.email "내아이디@users.noreply.github.com"
```

> ⚠️ **이메일은 GitHub의 "noreply 주소"를 쓰세요.** 커밋에는 이메일이 기록되어 **공개 저장소에 그대로 보여요.** GitHub 웹사이트 → **Settings → Emails** 에서 *Keep my email addresses private* 를 켜면 `숫자+아이디@users.noreply.github.com` 형태의 주소가 보입니다. 그 주소를 넣으세요.

### 4-4. 🧪 실습 4 · 첫 번째 세이브(커밋)

터미널에서 `my-portfolio` 폴더로 이동한 뒤 따라 하세요.

```bash
cd ~/dev/my-portfolio       # (Windows는 cd C:\dev\my-portfolio)
git init -b main
```
→ `.git` 이라는 숨김 폴더가 생겨요. *"이 폴더는 이제 Git 저장소!"* 라는 뜻입니다. (지우면 기록이 사라지니 건드리지 마세요.)

```bash
git status
```
→ `Untracked files: index.html` 이라고 나와요. **"Git이 아직 모르는 새 파일"** 이라는 뜻이에요.

```bash
git add index.html
git commit -m "docs: 나의 첫 웹페이지 추가"
```
→ 🎉 **첫 번째 세이브 완료!**

```bash
git log --oneline
```
→ 방금 저장한 기록이 한 줄 보여요.

> 📖 **커밋 메시지(저장 이름) 쓰는 법**
> 저장할 때 붙이는 짧은 설명이에요. 이 수업에서는 앞에 **꼬리표**를 붙입니다.
> | 꼬리표 | 뜻 | 예 |
> |:--|:--|:--|
> | `docs:` | 글·설명 문서 | `docs: 소개글 수정` |
> | `feat:` | 새 기능 추가 | `feat: 인사 버튼 추가` |
> | `style:` | 모양(CSS)만 바꿈 | `style: 배경색 변경` |
> | `fix:` | 잘못된 것 고침 | `fix: 오타 수정` |

### 4-5. 🅿️→🅲 AI가 고친 곳을 `git diff` 로 확인하기

> 🧠 **비유: 숙제 검사** AI가 내 파일을 고쳐 줬는데 **뭘 바꿨는지 모르면** 불안하죠? `git diff` 는 *"바뀐 곳만 빨간펜으로 표시해 주는 도구"* 예요. **🅲 코드 파트의 가장 중요한 도구**예요!

🅿️ **프롬프트 (범위를 좁혀서!)**
> ```text
> index.html 에서 맨 위 큰 제목의 글자만 "안녕하세요, 하늘의 코딩 일기입니다!" 로 바꿔 줘.
> 다른 부분은 절대 건드리지 마. 먼저 어떤 줄을 바꿀지 계획을 보여 주고, 내가 확인하면 고쳐 줘.
> ```
*(점검: 역할은 생략해도 되는 작은 수정이에요. ③ "건드리지 말 것"과 ⑤ "계획 먼저"는 꼭 들어갔죠?)*

🅲 **확인**
```bash
git diff
```
```text
-    <h1>안녕하세요, 저는 하늘입니다!</h1>
+    <h1>안녕하세요, 하늘의 코딩 일기입니다!</h1>
```
- `-` 로 시작하는 줄은 **지워진 것**, `+` 는 **새로 생긴 것**이에요.
- **제목 한 줄만** 바뀌었나요? 다른 줄도 바뀌었다면 → AI가 **약속을 어긴 거예요!** (되돌리기: `git restore index.html`)

마음에 들면 저장합니다.

```bash
git add .
git commit -m "docs: 제목 수정"
```
> 💡 `git add .` 의 `.` 은 "현재 폴더에서 바뀐 것 **전부**"라는 뜻이에요.
> 💡 **Git 명령은 AI에게 시키지 않고 내가 직접 입력해요.** 저장·올리기는 *내가 책임지는 단계*라서, 명령의 뜻을 몸으로 익히는 것이 좋아요.

## 5. 파트 4 · GitHub에 올려 인터넷에 공개하기 🌍

### Step 1. GitHub에 빈 저장소 만들기
1. `github.com` 로그인 → 오른쪽 위 **`+` → New repository**
2. 이렇게 입력합니다.

| 항목 | 입력 |
|:--|:--|
| Repository name | `my-portfolio` |
| 공개 범위 | **Public** (공개해야 Pages 사이트가 열려요) |
| Add a README file | ❌ **체크하지 않기** |

3. **Create repository** 클릭 → 화면에 나오는 주소(`https://github.com/내아이디/my-portfolio.git`)를 확인해 두세요.

### Step 2. 내 컴퓨터와 연결해서 올리기 (push)

```bash
git remote add origin https://github.com/내아이디/my-portfolio.git
git push -u origin main
```
처음에는 **브라우저 로그인 창**이 뜨면 로그인하면 됩니다. (안 되면 `gh auth login` 으로 로그인하는 방법이 있어요: 교수님께 질문!)

> ⚠️ `내아이디` 를 **내 GitHub 아이디**로 바꾸세요.

GitHub 저장소 페이지를 **새로고침**하면 `index.html` 이 올라가 있어요. 🎉

### Step 3. GitHub Pages로 웹사이트 공개

1. 저장소 → **Settings** 탭 → 왼쪽 메뉴 **Pages**
2. **Source** 를 **Deploy from a branch**, **Branch** 를 `main` / `/ (root)` 로 선택 → **Save**
3. **1~3분** 기다린 뒤 Pages 화면에 나오는 주소로 접속!

```text
https://내아이디.github.io/my-portfolio/
```

🎉 **내가 만든 웹페이지가 전 세계에 공개되었습니다!** 주소를 복사해서 친구나 가족에게 보내 보세요.

> 🔧 **사이트가 404로 나올 때**
> - 방금 설정했다면 **2~3분 더** 기다리기
> - 파일 이름이 정확히 `index.html`(소문자)인지 확인
> - Settings → Pages 에서 Branch가 `main` 인지 확인

### 앞으로의 루틴 (매 주차 반복!)

```text
1. 작업한다 (코드를 만들거나 고친다)
2. git add .  →  git commit -m "꼬리표: 설명"   (세이브)
3. git push                                       (인터넷에 올리기)
4. 1~2분 뒤 내 사이트에서 확인
```

```text
*.key

__pycache__/
```
